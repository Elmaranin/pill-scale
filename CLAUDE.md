# CLAUDE.md

Инструкции для Claude Code по работе с этим репозиторием.

## Что это

`pillscale` — платформа-весы под обычную таблетницу. Определяет по изменению веса,
что дозу извлекли, напоминает о приёме и (позже) уведомляет родственника.

Позиционирование: не «умная таблетница», а **приставка, превращающая обычную
таблетницу в контролируемую**. Пользователь не меняет свою коробку и привычки.

Проект учебный: над ним работает подросток 15+ вместе со взрослым.

Подробности — в `docs/`. Начинать с `docs/roadmap.md`: раздел «Сейчас» —
текущий шаг, «Первая версия: что осталось» — порядок работ.

Это **чистый публичный репозиторий** первой версии. Полная история разработки,
все эксперименты и черновики — в лабораторном репозитории `pill-scale-lab`
(папка `pillscale-lab` рядом). Сюда попадает только то, что нужно для сборки,
проверки и чтения проекта.

## Железо (кратко)

- MCU: **ESP32-C3** (плата типа SuperMini / DevKitM-1, нативный USB)
- Тензодатчик: из разобранных ювелирных весов, **500 г × 0.01 г**, 4 провода
- АЦП тензомоста: **HX711**. Второй АЦП (NAU7802) — вне первой версии; интерфейс
  `LoadCell` позволяет добавить его отдельным `*_cell.cpp` без изменения логики
- Сборка: **ESP-IDF 6.1** (поставлен через EIM), без Arduino
- Питание: **только USB от сети**. Батарейки невозможны: весы непрерывно следят
  за дрейфом и не могут спать, батареек хватило бы на 1–4 суток
  (`docs/hardware.md`, «Питание»)

Распиновка и подключение — `docs/hardware.md`.

## Архитектура

Три слоя, границы жёсткие:

- `src/board/` — железо: драйвер АЦП, USB-консоль, Wi-Fi, светодиод, зуммер.
  Всё, что зависит от ESP32.
- `src/algo/` — **portable C++**, без заголовков ESP-IDF и FreeRTOS. Фильтрация,
  детектор стабильности, конечный автомат «снята → возвращена → разбор», книга
  доз, журнал. Тестируется на хосте (`test/`, см. «Сборка»).
- `src/main.cpp` + `src/cmd.cpp` + `src/scale.cpp` + `src/logbook.cpp` +
  `src/web.cpp` — склейка, калибровка в NVS, командный интерфейс по USB,
  веб-страница.

`src/` — компонент ESP-IDF (вместо стандартной `main/`), его сборка —
`src/CMakeLists.txt`.

Драйвер АЦП реализует интерфейс `LoadCell` (`include/load_cell.h`). Пины и
опции — в Kconfig (`src/Kconfig.projbuild`, `idf.py menuconfig` → pillscale).

Проверка: `grep -rE "esp_|freertos|driver/" src/algo/` должен возвращать пусто.

## Командный интерфейс

Текстовый построчный протокол по USB (USB Serial/JTAG), описан в `docs/api.md`.
Любое изменение команд — сначала правка `docs/api.md`, потом код, потом
`tools/scale.py`. Протокол должен оставаться удобным и для человека в терминале,
и для скрипта.

## Сборка

ESP-IDF активируется в каждом новом терминале:

```
source ~/.espressif/tools/activate_idf_v6.1.sh
```

```
idf.py build flash monitor       # прошивка; выход из монитора — Ctrl+]
idf.py menuconfig                # пины, Wi-Fi, зуммер (меню pillscale)
cmake -S test -B test/build && cmake --build test/build && ctest --test-dir test/build
                                 # тесты алгоритмов на компьютере
python tools/scale.py --help     # утилита управления с компьютера
python tools/figures.py          # графики docs/img из docs/data
```

Поменял `sdkconfig.defaults` — удалить `sdkconfig`, иначе старые значения
останутся в силе. `idf.py fullclean` чистит только `build/`.

Журнал событий — во флеше, раздел `log` (`partitions.csv`); веб-страница —
Wi-Fi `pillscale`, http://192.168.4.1 (`docs/api.md`, «Веб-страница»).

## Стиль работы

- **Один шаг за раз.** Доводить текущую веху до рабочего состояния, потом
  следующую. Не генерировать сразу весь проект.
- **Алгоритмы отлаживаются на записанных данных**, а не на живом устройстве.
  Сначала логгер и CSV в `docs/data/`, потом код на хосте, потом прошивка.
- **Не писать регистры по памяти.** Тайминги HX711 — из даташита. Если не
  уверен, скажи прямо и укажи, что проверить.
- **Объяснять решения коротко.** Проект учебный: «почему так» важнее лишнего кода.
- **Предлагать эксперимент вместо спора** о параметрах (порог, окно усреднения,
  время стабилизации).

## Чего избегать

- Порога как единственного способа принять решение — это и есть то, что
  отличает проект от школьных аналогов
- Сравнения абсолютного веса через часы: дрейф тензодатчика больше таблетки.
  Сравниваем вес **до снятия и после возврата** — разница в секундах.
- Блокирующих ожиданий в главном цикле: там только опрос и `vTaskDelay(1)`
- Режимов сна и выключения моста/АЦП между измерениями: пропустим снятие коробки
  и добавим дрейф прогрева (`docs/hardware.md`, «Питание»)
- Облака, Telegram — до вехи, где они нужны по `roadmap.md` (своя точка
  доступа, страница с журналом и подключение к домашней сети только ради
  доступа к странице и NTP в ней — уже есть, веха 5)
- Библиотек «на всякий случай»
- Библиотек графиков с CDN на веб-странице: на демонстрации интернета нет,
  всё рисуется встроенным SVG/canvas из флеша
