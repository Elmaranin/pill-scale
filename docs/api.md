# Командный интерфейс

Текстовый построчный протокол по USB CDC, 115200 (для нативного USB скорость
фактически не важна).

Принципы:

- одна команда — одна строка; команды пишутся строчными, но регистр не важен;
- каждый ответ начинается с `OK` или `ERR`;
- данные в ответах — пары `ключ=значение` через пробел, чтобы их было легко читать
  глазами и разбирать скриптом;
- поток измерений — строки, начинающиеся с `D `, чтобы скрипт отличал их от ответов;
- события — строки, начинающиеся с `E `;
- строки, начинающиеся с `#`, — комментарии/лог, скрипт их игнорирует.

## Команды

### `ping`

```
> ping
< OK pong
```

### `info`

Версия, драйвер АЦП, текущая калибровка.

```
> info
< OK fw=0.1.0 adc=hx711 offset=-84213 scale=1987.42 sps=10
```

### `raw [n]`

Среднее из `n` сырых отсчётов АЦП (по умолчанию 10). Без калибровки — нужно для
отладки и для проверки, что датчик вообще жив.

```
> raw 20
< OK raw=-83950.3 n=20 sd=41.2
```

Сами отсчёты — целые, но среднее нет, поэтому `raw` с одним знаком после точки.
Отдельные отсчёты без усреднения — в `stream on`.
`sd` — стандартное отклонение по выборке, главный показатель шума.

### `read [n]`

Среднее из `n` отсчётов в граммах.

```
> read 50
< OK g=152.384 n=50 sd=0.021
```

### `tare [n]`

Обнулить по текущему весу (усреднение по `n`, по умолчанию 20). Сохраняется в NVS.

```
> tare
< OK offset=-84213
```

### `cal <grams> [n]`

Калибровка по грузу известной массы. Перед этим обязательно `tare` на пустой
платформе. Сохраняется в NVS.

```
> cal 100.00
< OK scale=1987.42
```

### `stream on [n] | off`

Непрерывный поток измерений, пока не придёт `stream off`.

Без `n` (или `n=1`) — каждый отсчёт АЦП, `raw` целое. С `n` — одна строка на
каждые `n` отсчётов, в ней их среднее (`raw` с десятыми). Блоки не перекрываются:
при 10 SPS и `n=5` — две строки в секунду. `n` от 1 до 600.

```
> stream on
< OK stream=on n=1
D 123456 -83950 0.132
D 123557 -83948 0.133
...
> stream on 5
< OK stream=on n=5
D 124012 -83950.4 0.132
D 124513 -83949.8 0.133
...
> stream off
< OK stream=off
```

Формат строки данных: `D <ms_since_boot> <raw> <grams>`, время — последнего
отсчёта в блоке.

Для анализа шума (веха 2) писать поток без усреднения: среднее можно посчитать
потом в Python, а сырые отсчёты из среднего уже не вернуть.

### `detect on | off`

Следить за весом и сообщать, когда что-то положили или сняли. Работает в фоне,
как `stream`, и вместе с ним. Нужна калибровка (`tare` + `cal`).

```
> detect on
< OK detect=on
E added delta=0.412 g=108.823
E removed delta=-0.398 g=108.425
> detect off
< OK detect=off
```

`delta` — изменение веса, `g` — новый вес.

Как решает (`src/algo/step_detector.h`):

1. Отсчёты собираются в блоки по ~1 с. Блок «спокойный», если разброс внутри
   него маленький; пока платформу трогают, блоки неспокойные и пропускаются.
2. Два спокойных блока подряд с одинаковым средним — вес установился.
3. Новый установившийся вес сравнивается с опорным («до»). Событие — только
   если разница одновременно больше 5 стандартных ошибок (это не шум) и не
   меньше 0.035 г (это не пылинка; ~половина самой лёгкой таблетки, 0.07 г).
4. Опорный уровень медленно (~20 с) подтягивается к спокойным блокам того же
   веса — так дрейф не накапливается. Блоки с другим весом его не двигают,
   иначе лёгкая таблетка, упавшая посреди блока, «съедается» по кусочкам.

Это упрощённая заготовка вехи 4: коробку не отличает от таблетки и дозу не
разбирает. Параметры подобраны на глаз, проверить на записях вехи 2.

### `event on | off`

Автомат «коробка стоит → снята → возвращена». **Работает всегда, если весы
откалиброваны** — запускается сам при включении, и все события пишутся в журнал
(`log`, веб-страница). `event on | off` только включает и выключает вывод строк
`E …` в USB.

```
> event on
< OK event=on
E placed g=26.941
E removed g=26.947
E returned delta=-0.143 off_s=7.3 g=26.804
E changed delta=-0.141 g=26.663
E missing off_s=512.0
> event off
< OK event=off
```

- `placed` — на пустую платформу поставили коробку (база записана).
- `removed` — коробку сняли; `g` — вес «до» (R1).
- `returned` — коробку вернули и она успокоилась; `delta` — изменение веса
  коробки по двум нулям `(R2 − Z2) − (R1 − Z1)`, `off_s` — сколько её не было,
  `g` — вес «после». Если успокоиться не удалось — ещё `ok=0`, `delta`
  ненадёжна.
- `changed` — вес коробки изменился, **пока она стояла** (взяли таблетку, не
  снимая коробку): `delta` — изменение, `g` — новый вес. Ждёт, пока руку уберут
  и вес установится (~2 с спокойствия); изменения меньше 0.035 г — дрейф, не
  событие.
- `missing` — коробки нет ~8.5 минут; сообщается один раз.

После каждого `returned` и `changed` — строка с разбором по выученным дозам
(`src/algo/dose_book.h`):

```
E none delta=0.008                    ничего не взяли (|delta| < 0.035 г)
E dose kind=2 n=7 g=0.143             доза вида 2, этот вид видели 7 раз
E dose kind=3 n=1 g=0.076 new         новый вид дозы (первый раз)
E double kind=2 g=0.290               двойная доза вида 2
E refill g=4.950                      коробка тяжелее — пополнили
E newbox g=-20.100                    вес изменился больше чем вдвое — другая коробка
E unsure                              коробка не успокоилась (`ok=0`), не судим
```

- **Вид дозы** — содержимое ячейки, сколько бы таблеток в ней ни было. Весы
  учат виды сами: новый вес — новый вид (`new`), повторился — подтверждён. До 4
  видов (утро/вечер, разные таблетки); места нет — заменяется самый редкий.
- `double` — только для подтверждённого вида (видели ≥ 2 раз) и если вес не
  подходит ни под один вид целиком.
- Выученные виды хранятся в NVS и переживают отключение питания.

Метод — `docs/experiments.md`, «Справка · Дрейф не ограничивает время без
коробки»; автомат — `src/algo/lift_tracker.h`.

### `doses`

Выученные виды доз: номер, вес одной дозы, сколько раз видели.

```
> doses
< OK n=3 1=0.544x5 2=0.143x16 3=0.076x1
```

### `reset doses`

Забыть выученные виды (сменили лекарства).

```
> reset doses
< OK
```

### `time [unix [tz]]`

Узнать или установить время. Часов с батарейкой нет: после включения время
неизвестно, пока его не пришлют — браузер (веб-страница делает это сама) или
компьютер.

```
> time
< OK known=0 uptime_s=5123
> time 1793001600 180
< OK known=1 unix=1793001600 tz=180
```

`unix` — секунды с 1970-01-01 UTC, `tz` — смещение местного времени в минутах
(Москва — 180).

### `log [n] | log clear`

Журнал событий во флеше (~8000 записей, около месяца). Переживает отключение
питания; заполнился — новые записи затирают самые старые.

```
> log 3
L 412 boot=7 up=8123 t=2026-10-25T08:05:12 dose kind=1 off=9 d=-0.131 g=26.248
L 413 boot=7 up=8400 t=2026-10-25T08:09:49 status g=26.249
L 414 boot=7 up=9000 t=- removed g=26.250
< OK n=3 total=414
> log clear
< OK
```

Поля: номер записи, номер включения, секунды от включения, местное время (`-` —
неизвестно), событие, вид дозы, сколько секунд не было коробки, изменение и вес
в граммах.

Время записей, сделанных до установки часов, восстанавливается: если в том же
включении время позже стало известно, оно пересчитывается по секундам от
включения — и сразу, и после перезагрузки. `-` остаётся, только если за всё
включение время так и не узнали (питание пропало раньше): сколько весы были
выключены, неизвестно. В `/log.csv` столбец `unix` — то, что записано во флеш
(`0` — время при записи было неизвестно), `local_time` — с восстановлением. События: `boot`, `time`, `placed`, `removed`, `missing`, `none`,
`dose`, `double`, `refill`, `newbox`, `unsure`, `status` (вес раз в 10 минут —
для дрейфа).

### `net`

Состояние сети и веб-сервера — когда стартовые сообщения уже не видны.

```
> net
< OK wifi=ap ssid=pillscale ip=192.168.4.1 clients=1 web=on
> net
< OK wifi=sta ssid=Home ip=192.168.1.37 web=on
```

`wifi=ap` — весы раздают свою сеть; `wifi=sta` — подключены к домашней
(адрес выдал роутер, страница — по этому `ip`); `wifi=off` — сеть не поднялась.
`clients` — только в режиме `ap`.

### `wifi [ssid [password]] | wifi clear`

Домашняя сеть Wi-Fi: узнать, задать или забыть. Хранится в NVS, применяется
при следующем включении (`reboot`). При включении весы 30 с пытаются
подключиться к этой сети; не вышло — поднимают свою точку `pillscale`, как
раньше. Имя и пароль через USB — без пробелов (строка разбивается по пробелам);
с пробелами — через веб-страницу, вкладка «Настройки».

```
> wifi
< OK set=0
> wifi Home secret123
< OK set=1 ssid=Home
> wifi clear
< OK set=0
```

Пароль не показывается. Пустой пароль — открытая сеть.

### `beep [ms [hz]]`
Пискнуть зуммером на `ms` миллисекунд (по умолчанию 200, не больше 5000) —
проверка, что он подключён. Не блокирует: команда отвечает сразу. Пассивный
зуммер звучит меандром на частоте из `menuconfig` (Buzzer tone, по умолчанию
2700 Гц); `hz` (100–10000) задаёт частоту только для этого сигнала — так ищут
резонанс: где громче всего, ту частоту и ставить в `menuconfig`. Для активного
зуммера частота 0 — просто высокий уровень, `hz` игнорируется.
```
> beep 500
< OK ms=500 hz=2700
> beep 500 3200
< OK ms=500 hz=3200
```
Если пин зуммера в `menuconfig` равен −1 — `ERR no_buzzer`.

### `reboot`

Перезагрузить весы (кнопка RESET внутри корпуса недоступна).

```
> reboot
< OK
```

## Веб-страница

Весы сами раздают Wi-Fi: сеть `pillscale`, пароль задаётся в `idf.py menuconfig`
→ pillscale (по умолчанию `pillscale`). Подключиться с телефона и открыть
**http://192.168.4.1**.

Если во вкладке «Настройки» задана домашняя сеть, при включении весы сначала
30 с пытаются подключиться к ней. Получилось — своя точка не поднимается,
страница доступна по адресу, который выдал роутер (его печатает команда `net`
и стартовое сообщение в USB). Не получилось — своя точка, как обычно.
В домашней сети весы ещё берут время с NTP (`pool.ntp.org` по умолчанию) —
после пропадания питания оно появляется само, без открытия страницы. Больше
ничем из интернета весы не пользуются.

| Адрес                   | Что                                                                                                                                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                        | Состояние, выученные дозы, последние события. При открытии страница сама присылает весам время телефона    |
| `/scale`                   | Вкладка «Весы»: вес в реальном времени крупно, кнопка «Тара», сырые отсчёты АЦП мелко — для демонстрации                                          |
| `/live.json`               | Вес сейчас для вкладки «Весы» (страница спрашивает ~4 раза в секунду)                                                                               |
| `POST /tare`               | Тара для вкладки «Весы»: текущий вес становится нулём **только на экране**                                                                          |
| `/settings`                | Настройки: домашняя сеть Wi-Fi (имя, пароль), кнопка перезагрузки                                                                                  |
| `/log.csv`                 | Весь журнал в CSV — для анализа и графиков                                                                                                                          |
| `/status.json`             | Состояние для программ                                                                                                                                                         |
| `POST /time?unix=…&tz=…` | Установить время (так делает страница)                                                                                                                             |
| `POST /settings`           | Сохранить домашнюю сеть: тело формы `ssid=…&pass=…` (пустой `ssid` — забыть сеть). Применяется после перезагрузки |
| `POST /reboot`             | Перезагрузить весы                                                                                                                                                                |

Интернет не нужен ни весам, ни телефону.

### Вкладка «Весы»

Обычные весы на телефоне: вес — среднее последних 8 отсчётов (~0.7 с), до сотых
грамма; отметка «стабильно», когда разброс этих отсчётов меньше 0.03 г. Мелким
шрифтом — как получаются граммы: сырой отсчёт АЦП, ноль калибровки, отсчётов на
грамм и формула `г = (отсчёт − ноль) / отсчётов на грамм`.

**Тара здесь не та, что команда `tare`.** Команда `tare` переписывает ноль
калибровки во флеше: с коробкой на весах автомат увидел бы, что вес «пропал», и
записал бы ложное «сняли». Кнопка «Тара» на вкладке только запоминает текущий вес
в памяти и вычитает его из показания на экране — калибровка, автомат и журнал не
меняются. Нажать на пустой платформе — тара снова 0. После перезагрузки тара 0.

Дрейф вкладка не вычитает: при смене температуры показание может уплыть на
сотые–десятые доли грамма — для взвешивания «здесь и сейчас» это не важно.

```
GET /live.json
{"calibrated":true,"raw":8312456,"offset":-84213,"scale":1987.42,
 "g":26.251,"tare":0.000,"net":26.251,"sd":0.012,"stable":true,"n":8}
```

`raw` — последний сырой отсчёт; `g` — вес брутто, г (среднее `n` отсчётов);
`net` — `g − tare`; `sd` — разброс отсчётов, г. Не откалиброваны —
`"calibrated":false`, граммы не считаются.

```
POST /tare
OK tare=26.251
```

### `reset cal`

Сбросить калибровку к значениям по умолчанию.

## Ошибки

```
< ERR unknown_command
< ERR bad_argument
< ERR adc_timeout
< ERR not_tared
< ERR not_calibrated
```
